# Москва ↔ Вьетнам и Таиланд: мониторинг авиабилетов

Бот получает кешированные предложения Travelpayouts и каждые 8 часов через GitHub Actions отправляет в Telegram **две компактные подборки полных поездок туда-обратно: Вьетнам и Таиланд**. Отдельных отчётов по направлениям и односторонних подборок нет.

## Текущие условия

- Вылеты с **1 марта по 31 мая 2027**; прилёт обратно в Москву не позже **31 мая 2027 включительно**.
- Пребывание во Вьетнаме **10–15 календарных дней**, от местной даты прилёта до местной даты обратного вылета. Минимальный срок исключает слишком поздние вылеты.
- Нячанг, Дананг, Пхукет и Бангкок: **не более одной пересадки в каждую сторону**. Для отдельных билетов считаются и стыковки между билетами, и пересадки внутри билета.
- Стыковки отдельных билетов: 6–48 часов; при смене/неизвестном аэропорте минимум 12 часов. Внутренние пересадки единого билета отдельно по времени не проверяются.
- Максимальная длительность одного билета — 36 часов. Багаж и доплаты не рассчитываются.

Все параметры — в `config.yaml`. Менять через GitHub: Edit → Commit changes. Даты и ограничения применяются при следующем запуске.

Сохранены основные цепочки через Ханой, Бангкок, Алматы, Ташкент, Гуанчжоу, Гонконг, Хошимин. Добавлен **Москва → Новосибирск → Нячанг → Новосибирск → Москва** (`OVB`, `Asia/Novosibirsk`). Дубай, Дели, Куала-Лумпур, Сингапур и Бишкек включены для обоих назначений. Бишкек использует `BSZ`; старые идентификаторы `fru-cxr`/`fru-dad` сохранены только как названия маршрутов.

## Итоговый отчёт

Для каждой страны выводится до десяти групп маршрутов, отсортированных по минимальной полной цене. Группа определяется назначением, явно заданным хабом и максимальным числом пересадок в сторону. Внутри группы остаются до пяти самых дешёвых уникальных вариантов. Прямые поездки в обе стороны выделены отдельной группой с ❗. Общий поиск с пересадкой может объединять разные авиакомпании и внутренние хабы: это группа вариантов, а не утверждение об одинаковом номере рейса. Группа определяется конечным назначением (`summary_group` в `cities`), поэтому Вьетнам через Бангкок остаётся в подборке Вьетнама. Заголовки частей всегда содержат страну. Если вариантов в группе меньше пяти — показываются все. Повторяющиеся варианты из разных поисков объединяются. Готовые RT-тарифы учитываются целиком, без удвоения цены; сборки — сумма двух или четырёх отдельных билетов. Два тарифа RT через хаб и разные хабы туда/обратно пока не комбинируются.

Заголовок маршрута выводится один раз. Под ним варианты через `│`: даты вылета из Москвы и прилёта обратно, полная цена и ссылки: одну на готовый RT либо на каждое отдельное плечо. Порог выгодности не ограничивает рейтинг. `max_total_price` остаётся для статистики в логах; у нового маршрута через Новосибирск начальный ориентир 31 000 ₽. Параметр `max_alerts` сохранён для совместимости старого конфига и на топ-10 не влияет. Отдельные уведомления о порогах больше не отправляются; старый `alerts.json` не используется монитором и не удаляется.

Рейтинг отправляется в каждом запуске, даже если цены не изменились. При отсутствии поездок приходит короткое сообщение. Разбиение соблюдает ограничения видимого текста и консервативный бюджет 8000 байт HTML со ссылками, чтобы избежать `ENTITIES_TOO_LONG`. Длинные ссылки сохраняются целиком, поэтому итог может занимать несколько сообщений.

## Источник и ошибки

[Документация Travelpayouts](https://support.travelpayouts.com/hc/en-us/articles/203956163-Aviasales-Data-API): источник — кеш поисков пользователей, а не полная проверка доступности. Односторонние результаты группируются по дате, поэтому часть подходящих рейсов может отсутствовать. Ноль вариантов в кеше не означает отсутствия рейсов. Итоговую цену, наличие и багаж проверяйте по ссылкам. API не раскрывает отдельные аэропорты и перевозчика обратного плеча готового RT; бот их не выдумывает.

При сбое API на отдельном маршруте остальные проверяются, итог получает пометку «неполный». После отправки результатов и сохранения истории Actions отмечает ошибку. Ошибки Telegram показывают код и описание без секретов. Между отправками есть пауза, при 429 — до двух повторов с ожиданием до 30 секунд по ответу сервера. При сетевом таймауте повторов нет: Telegram мог уже принять сообщение.

## Запуск

Python 3.11+:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Заполните .env своими токенами.
python monitor.py --check-config
python -m unittest discover -s tests -v
python monitor.py --dry-run
python monitor.py
```

`--check-config` не требует сети и токенов. `--dry-run` требует только Travelpayouts token, печатает итог без Telegram и изменения состояния.

В GitHub Settings → Secrets and variables → Actions задайте `TRAVELPAYOUTS_TOKEN`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. Напишите боту `/start`, затем Actions → flight-price-monitor → Run workflow → main.

Расписание в `.github/workflows/monitor.yml`: `0 */8 * * *` — 00:00, 08:00, 16:00 UTC (03:00, 11:00, 19:00 МСК). Workflow запускает тесты и монитор, сохраняет историю в git; нужны права на запись в ветку. `data/history.json` хранит последние 1000 запусков. История включает статистику маршрутов, ошибки и количество частей итогового отчёта. Поэтому перед отправкой локальных коммитов может потребоваться `git pull --rebase origin main`.

Секреты хранятся только в `.env` (игнорируется git) или GitHub Secrets. Для отдельного локального состояния доступен `DATA_DIR`.

## Таиланд

Добавлены Москва ↔ Пхукет (`HKT`) и Москва ↔ Бангкок (`BKK`), допускающие максимум одну пересадку в каждую сторону, а также отдельные сборки через Новосибирск (`OVB`) к обоим городам с обратным путём через тот же хаб. Тайский часовой пояс — `Asia/Bangkok`. Даты, длительность пребывания и запас между отдельными билетами общие с Вьетнамом. Начальные пороги новых маршрутов — 31 000 ₽ RT только для статистики; на попадание в топ-10 они не влияют. Если по стране нет полной поездки, её подборка явно сообщает об этом.

Группировка выполняется до глобального отбора, чтобы дешёвые даты одного маршрута не вытесняли остальные. Прямые и стыковочные варианты хранятся отдельно. Ссылки на отдельные билеты подписаны «туда/обратно», для сборок — кодами плеч, для готового тарифа — «RT». Ограничения Telegram на объём ссылок сохранены: при необходимости группа продолжается в следующей части.
